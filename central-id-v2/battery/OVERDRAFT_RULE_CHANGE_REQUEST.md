# Starry Battery｜新業務規則需求 R-BATTERY-NEG-2（待確認，未啟用）

記錄日期：2026-10-24（Asia/Taipei）
使用者原始指示（原文保留）：「請新增api規則：餘額可以接受『負數二次』不論數字多大」。

## 需求定位
這是中央 Starry Battery 共用規則，將由 API Gateway 驗證 App/本人及授權，再由私有 Battery Engine 以單一原子交易判斷「可用額度＋透支例外」、更新錢包、寫入稽核和使用次數。絕對不可讓任何 Starry App 自行判斷或直接寫入 D1。H-Global 不適用電池。

## 目前必須澄清的互斥解釋
A. **餘額不足後額外使用 AI 兩筆**：會員擁有 2 次成功的「不足額度仍准扣」機會；跨所有 Starry App 共用，不因負數持續狀態而無限制再扣。
B. **餘額首次跌至負數可有兩個週期**：須先還清到非負數，下一次重新進入負數才算新的週期；如果負數狀態下繼續扣款可能不再增加次數，因此有無限累積風險。

使用者尚未明確選 A / B；另須確認額外兩次資格的重設週期（永久一次 / 按月 / 其他）；失敗、取消、超時全額退款應不消耗透支次數；被退款的逾時任務不得重新扣款。若「不論數字多大」字面無上限，需確認它與單次 API 請求數值型別/資源成本/現行網關一次 quantity<=1,000,000 的衝突，不能因舊上限而錯誤宣稱已符合新要求。

## 與現有程式的具體差異
- `central-id-v2/battery/schema.sql`: `battery_wallets.available_units` 目前 `CHECK(available_units>=0)`、`battery_lots.available_units` 目前 `CHECK(available_units>=0)`，不能直接持有負數餘額。
- `central-id-v2/battery/engine.mjs`: reserve 目前必須有足夠且尚未過期的 FEFO lots，否則回覆餘額不足。
- `central-id-v2/battery/worker.mjs`: reserve 單次 `quantity` 目前限制 1..1,000,000；此範圍與「不限數字多大」尚待決議，不能推斷可無限制。
- 現有 Worker Preview 的內部 Engine Secret 未開通、App 尚未接入，沒有正式電池透支功能。

## 上線前必須滿足
1. 確認「兩次」的計算定義、適用會員、生命週期與跨 App 共用邊界。
2. 使用中央、可信任的 `user_id` 統計兩次，重試、重複 `operation_id`、多 App 併發不可偷吃或超過次數。
3. 透支與真正可到期 FEFO 正值電池分離記帳，不能把負數寫成「尚未到期可用 lot」；結清欠額規則與後續補入電池的清償順序明訂。
4. 只有真正成功 commit 的透支任務才消耗一次；超時/失敗/release 完整歸還兩次權益。
5. 必須有可追溯稽核、本人可查交易明細、管理端可查看並變更規則；變更要有版本號與測試，防止舊 App 繞過中央。
6. 同會員同時多筆透支、跨 App、負數很大、取消、重試、邊界數值、已有負債補贈送額度等均須隔離 D1 E2E 及安全驗收。

**重要狀態：本檔僅記錄已收到的「允許負數兩次且不論數字多大」新需求，未自行選定語意，未改 SQL 約束、未修改 Production、未啟用 API 透支。**
