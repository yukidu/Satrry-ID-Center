## 操作方法與邊界

- 使用同一個已授權 Cloudflare 帳號的 D1 API，讀取來源 sqlite_schema 的業務表定義，先在新資料庫建立表，再依列讀取資料及安全轉義值並寫入隔離副本，最後建立來源有定義的索引與觸發器。
- 不直接複製 Cloudflare 管理的 `_cf_KV` 或 SQLite 內部 `sqlite_sequence` 系統表（目標 D1 自行維護）；其餘 61 張業務表均建立並複製資料。
- 表內容採相同列順序逐表讀取及比對校驗；符合本次複製的內容一致性要求，但**這不是單一原子時間點的完整資料庫快照**，正式遷移前仍需明確定義來源寫入窗口、再核對與切換策略。
- 複製庫含舊 Starry 的 Session、App 授權紀錄、Battery 等私密業務資料；一律隔離存放。**不可把舊 Session/token 當作新版登入授權，不能直接在 H-Global 入口讀取 Starry 電池資料**。
- 新版中央會員服務使用獨立 `central_id_v2` D1；未完成正式欄位映射、身份驗證、審核結果證明、隱私與授權測試前不自動灌入「已核准會員」狀態，也不讓舊庫資料出現在新公開名錄。

## 網站與發布

- 新站 Worker：`hglobal-central-id-v2`，唯一公開網址 `https://id.hglobal1985.com`。
- 目前只提供公開資訊、FAQ、狀態健康檢查；寫入 API 回傳 503，無 OAuth、無可搜尋的私人會員資料。
- 舊站 `id.starry.phd` 完全獨立，不互連、不轉址、不做即時同步。
- 相關 GitHub 測試涵蓋狀態宣告、不可透過新網站讀寫資料、禁止未開啟的登入能力；複製檢查及資料稽核結果在本檔留存。
